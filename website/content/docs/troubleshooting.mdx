---
title: Troubleshooting
description: Fixes for the most common problems, starting with spmx doctor.
---

Start with the diagnosis:

```bash
spmx doctor
```

## The shims do nothing

`spmx doctor` shows the **PATH Shims Ordering** check. `~/.spmx/shims` has to come before `flutter`, `xcodebuild` and `swift`:

```bash
export PATH="$HOME/.spmx/shims:$HOME/.spmx/bin:$PATH"
```

Open a new shell afterwards. Check with `which flutter`; it should point into `~/.spmx/shims`.

## Packages are copied, not cloned

The **APFS Filesystem** check failed: the store and the worktree are on different volumes, or the volume is not APFS. Move the store with `SPMX_STORE_DIR` to the same volume as your projects. Run `spmx hydrate --verbose` to see which method each package used.

## A new worktree still downloads everything

The store has nothing for those pins yet. Build once in any worktree so the shim can harvest, or run `spmx migrate <dir> --apply` to import existing caches. `spmx status` shows how many pins are cached.

## The Xcode app does not benefit

Xcode ignores your shell `PATH`. Enable the hook so worktrees are hydrated at creation:

```bash
spmx hooks enable --global
```

## My checkout changes were not replaced

By design: `hydrate` never overwrites a checkout you modified. Pass `--force` to replace it.

## Skip spmx for one command

```bash
SPMX_DISABLE=1 xcodebuild ...
SPMX_NO_COMPILE_CACHE=1 xcodebuild ...
SPMX_VERBOSE=1 flutter run          # print what the shim is doing
```

## The store is large

```bash
spmx store status
spmx store prune --dry-run
spmx store prune --older-than 7
```
