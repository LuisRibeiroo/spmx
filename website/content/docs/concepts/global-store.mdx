The store lives at `~/.spmx/store`. Override the location with `SPMX_STORE_DIR`. It must be on the same APFS volume as your projects and `DerivedData` for zero-copy clones; see [APFS clonefile](/docs/concepts/apfs-clonefile) for what happens otherwise.

## Layout

| Kind | Path | Keyed by |
| :--- | :--- | :--- |
| Source checkouts | `checkouts/<identity>-<revision>/` | package identity and Git revision |
| Bare Git repos | `repositories/<identity>/` | package identity (shared across versions) |
| Binary artifacts | `artifacts/<identity>/<target>-<checksum>/` | package, target and checksum |
| Macro prebuilts | `prebuilts/<toolchain-hash>/<package>-<version-or-checksum>/` | Swift and Xcode version, then package |
| Index | `index.json` | linked projects, pinned versions, excluded projects, toolchain fingerprint |

Multiple versions of the same package (for example `firebase 1.0.0` in `c-137` and `firebase 1.0.1` in `c-131`) coexist side by side in `checkouts/` and share the bare Git repository in `repositories/firebase-ios-sdk/`. Prebuilts are partitioned by a hash of `swift --version` and `xcodebuild -version` so an Xcode update never serves a stale module ABI.

## Hydrate and harvest

- [`spmx hydrate`](/docs/commands/hydrate) reads `Package.resolved`, clones every matching checkout, bare repository, artifact, and prebuilt into `SourcePackages` (or `.build`), and preserves the native `workspace-state.json` schema even on partial cache hits so SwiftPM only downloads missing deltas.
- [`spmx harvest`](/docs/commands/harvest) verifies that each Git checkout has a clean working tree (`git status --porcelain`) and matching `HEAD` revision before copying it into the store, preventing local debug edits from leaking to other projects.

The shims run both automatically. Projects opted out with [`spmx unlink`](/docs/commands/unlink) or `.spmxignore` are bypassed cleanly.

## Concurrency

Every write to the store takes a per-package `flock` and goes through atomic staging, so multiple projects, worktrees, or AI agents can hydrate and harvest at the same time.

## Inspecting and cleaning

```bash
spmx store path      # print the store location
spmx store list      # list cached (package, version) slices and linked projects
spmx store status    # per-project breakdown and total disk saved across the machine
spmx store prune     # drop entries no linked project references
```
